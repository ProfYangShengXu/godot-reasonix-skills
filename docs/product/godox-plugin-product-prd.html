🔌 Godox Plugin

Godot 编辑器内 Agent 桥接插件 — 让 AI Agent 直接操控编辑器 API
产品设计文档 v1.0 · 2026-07-12 · 后续由 pipeline 架构师转换为技术 PRD
1. 背景与目标

现实问题

当前 Godot Reasonix 技能集通过文件操作 + CLI 与 Godot 交互——写入 .tscn、生成 .gd、调用 --headless 验证。这种方式有四个根本性局限：

  • .tscn 格式无官方 schema——Agent 用字符串模板生成场景文件，但 Godot 小版本升级可能破坏格式兼容性。每次 Godot 更新（4.0→4.1→4.2）都有节点属性名变化，技能集需要手动适配。
  • --headless 不能模拟输入——Godot 的无头模式没有键盘/鼠标输入 API。M9 输入模拟器用 OS 级别的 xdotool/SendKeys 发送按键，脆弱且需要窗口焦点。
  • 日志解析靠正则猜——M8 的 ParseLogText 用 7 种正则匹配器识别错误格式，但 Godot 日志格式在小版本间有变化，且无法获取完整调用栈和变量值。
  • 无法操控运行时——不能设断点、不能读取变量、不能单步调试。Agent 看到的只有「跑完后的一堆文字」，而非「跑到一半时编辑器里的状态」。

一句话定位

「像 VSCode Copilot 有 Language Server 一样，给 Godot Reasonix 技能集一个原生编辑器 API 通道。」

更具体地说：一个 Godot 4.x EditorPlugin，通过 MCP 协议暴露编辑器和运行时 API，让 Agent 不再猜文件格式，而是直接问 Godot「这个场景结构是什么」「这个属性设对了没有」「这个脚本跑起来报什么错」。

4. MVP 定义

🥇 Must-have（MVP 必须包含）

  • P0 MCP Server 核心 —— 插件启动一个 stdio MCP server，暴露场景操作接口：get_scene_tree（返回当前打开场景的节点树）、add_node（添加子节点）、remove_node、set_node_property、attach_script
  • P0 输入中继基础 —— 插件开启 UDP socket，接收 Agent 发送的按键事件并调用 Input.parse_input_event() 注入
  • P0 结构化日志通道 —— 插件拦截 Godot 的 print() 和 push_error()，通过 socket 以 JSON 格式实时推送给 Agent
  • P1 场景验证 —— validate_scene(path) 调用 ResourceLoader.load() 验证 .tscn 文件是否可加载，返回精确错误信息
  • P1 插件自动发现 —— Agent 技能集检测 Godot 项目是否安装了 godox-plugin，自动切换到插件模式而非文件操作模式

📅 Nice-to-have（一期后加）

  • P2 调试桥 —— 设置/移除断点、读取调用栈、检查变量值（需 EditorDebuggerPlugin）
  • P2 鼠标事件模拟 —— 注入鼠标点击、移动、拖拽事件
  • P2 游戏截图通道 —— 插件截取 Viewport 画面并返回给 Agent（替代 OS 级截图）
  • P3 资源浏览器 API —— 列出项目资源、导入新资源、刷新文件系统
  • P3 信号连接可视化 —— 返回场景中所有信号连接的关系图

🚫 明确不做什么

  • 不做 编辑器 UI 扩展 —— 不添加新的面板、按钮、dock。插件在后台作为 MCP server 运行，没有用户界面
  • 不做 Godot 3.x 兼容 —— 锁定 Godot 4.x（EditorPlugin API 在 3.x 和 4.x 不兼容）
  • 不做 多人协作 —— 一个编辑器实例只服务一个 Agent 连接
  • 不做 Web 导出 —— 插件只在桌面版编辑器中运行

7. 设计理念

体验关键词

零配置 透明代理 优雅降级

  • 零配置（Zero Config） —— 插件安装即用。Agent 技能集自动检测编辑器是否运行、插件是否加载，无需用户手动启动 MCP server 或配置端口。
  • 透明代理（Transparent Proxy） —— Agent 调用插件 API 就像直接调用 Godot 编辑器内部函数一样，不需要关心序列化格式、端口管理、连接重连。插件只是"让编辑器可以被代码调用"。
  • 优雅降级（Graceful Degradation） —— 如果插件未安装或编辑器未运行，技能集自动 fallback 到现有的文件操作模式。用户不会看到报错，只会看到 Agent 说"走文件模式"。

核心交互原则

  1. 编辑器在，走插件；编辑器不在，走文件。 自动检测、自动切换，用户无感知。
  2. 每次操作都有确认回读。 插件写入场景属性后，立即回读确认值与预期一致。不信任"写进去就对了"。
  3. MCP 是唯一接口。 不额外暴露 HTTP API 或 WebSocket——统一走 Reasonix 原生 MCP 协议，减少攻击面和维护成本。

视觉风格方向

插件没有用户界面。面向用户的「界面」是 Agent 控制台的日志输出：

  • 插件连接成功：[godox] ✅ 已连接到 Godot 编辑器 (v4.3)
  • 插件操作场景：[godox] 📦 set_node_property(Player, position, {x:100, y:200}) → OK
  • 插件验证场景：[godox] ✅ scenes/Level.tscn — 可加载，2 warnings
  • 降级到文件模式：[godox] ⚠️ 编辑器未运行，切换到文件操作模式

整体调性：可靠、透明、不打扰——让用户感觉"编辑器本身在帮 Agent 做事"。

8. 风险
风险类别风险描述可能性影响缓解措施
市场风险 市场需求过小——「用 AI Agent 调试 Godot」是一个极细分的需求 高 中 插件作为免费开源工具发布，不依赖插件转化收入；它提升现有技能集的价值，而非独立获客
运营风险 Godot EditorPlugin API 在 4.x 小版本间有破坏性变更 中 高 锁定最低支持版本（如 4.3+），文档中明确声明兼容范围；CI 用多个 Godot 版本测试
运营风险 MCP stdio 模式下插件的进程生命周期管理复杂（编辑器退出时插件进程未清理） 中 中 插件在 EditorPlugin._exit_tree() 中强制清理子进程；Agent 侧设超时兜底
增长风险 冷启动——没有用户知道这个插件存在 高 中 插件随 Godot Reasonix 技能集 v3.0 一起发布；在 Godot Asset Library 上架；在 r/godot 和 AI 编程社区发布 Demo 视频
变现风险 开源插件无法直接变现 中 低 插件本身不开源也不收费——它提升技能集的价值，技能集通过企业许可证/LLM API 代理变现
